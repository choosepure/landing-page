# Design Document: Test Report Collection

## Overview

This design defines the complete MongoDB document schema for the `test_reports` collection, the required indexes, and the updates to the Admin API endpoints to support all report fields. The existing collection and API endpoints in `server.js` will be extended to accommodate the full set of report data fields identified from the HTML report pages and mobile app.

## Architecture

### Storage Layer

- **Database**: MongoDB Atlas (`choosepure_db`)
- **Collection**: `test_reports`
- **Driver**: `mongodb` Node.js driver (MongoClient) — already in use
- **No ODM**: The project uses raw MongoClient, not Mongoose. Schema enforcement is done at the application layer in the API validation logic.

### Document Schema

```javascript
{
  // === Report Metadata ===
  _id: ObjectId,                    // Auto-generated by MongoDB
  productName: String,              // Required. e.g., "Akshayakalpa Organic Cow Pasteurised Milk"
  brandName: String,                // Required. e.g., "Akshayakalpa Farms & Foods Pvt Ltd"
  category: String,                 // Required. e.g., "Milk · Organic"
  batchCode: String,                // e.g., "AESLPH4"
  labName: String,                  // e.g., "Bangalore Analytical Research Center (NABL)"
  labReportNumber: String,          // e.g., "BARC/25/09/0826" — unique sparse index
  reportDate: Date,                 // Date the lab report was issued
  testDate: Date,                   // Date testing was performed
  sampleCondition: String,          // e.g., "Good · 500 ml"
  totalParametersTested: Number,    // e.g., 290
  origin: String,                   // e.g., "Palladam, Tamil Nadu"
  shelfLife: String,                // e.g., "5 days from packaging"
  barcode: String | null,           // 13-digit EAN barcode or null
  imageUrl: String,                 // Required. Product image URL

  // === Purity Scoring ===
  purityScore: Number,              // Required. 0–100
  scoreVerdict: String,             // e.g., "Outstanding", "Excellent", "Good", "Moderate", "Concern"
  scoreFormula: String,             // Explanation of score calculation
  categoryScores: [                 // Array of category-level scores
    {
      categoryName: String,         // e.g., "Pesticide Residues"
      score: Number,                // Category score value
      description: String           // Brief description of category result
    }
  ],

  // === Detailed Test Parameters ===
  testParameters: {                 // Object keyed by category
    "Microbiology": [
      {
        parameterName: String,      // e.g., "Total Plate Count"
        result: String,             // e.g., "< 10", "0.002", "Not Detected"
        unit: String,               // e.g., "CFU/ml", "mg/kg", "ppm"
        fssaiLimit: String,         // e.g., "50000 CFU/ml"
        euLimit: String,            // e.g., "100000 CFU/ml"
        usFdaLimit: String,         // e.g., "Not specified"
        status: String              // "Pass" | "Fail" | "Context" | "NA"
      }
    ],
    "Heavy Metals": [...],
    "Pesticides": [...],
    "Antibiotics": [...],
    "Nutrition": [...],
    "Adulterants": [...]
  },

  // === Content & Commentary ===
  expertCommentary: String,         // Expert analysis text
  methodology: String,              // Testing methodology description
  parentSummary: String,            // "What Parents Should Know" section
  recommendations: [                // Array of recommendations
    {
      severity: String,             // e.g., "info", "warning", "positive"
      title: String,                // Recommendation title
      description: String           // Recommendation detail
    }
  ],

  // === Statistical Summary ===
  stats: {
    totalParameters: Number,        // Total parameters tested
    passCount: Number,              // Parameters that passed
    contextNotes: Number,           // Parameters with context notes
    safetyConcerns: Number          // Parameters with safety concerns
  },

  // === Comparisons ===
  comparisons: [                    // Array of comparison entries
    {
      productName: String,          // Compared product name
      score: Number,                // Compared product score
      rating: String                // e.g., "Outstanding", "Good"
    }
  ],

  // === Admin/System Fields ===
  published: Boolean,               // Default: true. Controls public visibility
  isPremium: Boolean,               // Default: false. Requires subscription to view
  pdfUrl: String,                   // URL to pre-generated PDF
  reportUrl: String,                // URL path to web HTML report
  statusBadges: [String],           // e.g., ["FSSAI Compliant", "Organic Certified"]
  createdAt: Date,                  // Auto-set on insert
  updatedAt: Date                   // Auto-set on insert and update
}
```

### Indexes

| Index | Fields | Options | Purpose |
|-------|--------|---------|---------|
| Published listing | `{ published: 1, createdAt: -1 }` | — | List published reports chronologically |
| Category filter | `{ category: 1 }` | — | Filter by product category |
| Barcode lookup | `{ barcode: 1 }` | `sparse: true` | Lookup by EAN barcode |
| Brand filter | `{ brandName: 1 }` | — | Filter by brand |
| Lab report dedup | `{ labReportNumber: 1 }` | `unique: true, sparse: true` | Prevent duplicate lab reports |

### API Changes

#### POST `/api/admin/reports` — Extended Fields

The existing endpoint will be updated to accept and store all new fields. Required fields remain: `productName`, `brandName`, `category`, `imageUrl`, `purityScore`, `testParameters`. All other fields are optional with sensible defaults.

#### PUT `/api/admin/reports/:id` — Partial Update

The existing endpoint will be updated to accept any subset of the new fields. Only fields present in the request body are updated. Validation rules apply to any field that is provided.

#### GET `/api/reports/:id` — Full Document

Already returns the full document from MongoDB. No changes needed — new fields will automatically be included in the response.

#### GET `/api/reports` — List Endpoint

The list endpoint already returns a subset of fields. It will be updated to also include `labName`, `totalParametersTested`, and `scoreVerdict` in the mapped response for richer list cards.

## Correctness Properties

### Property 1: Purity Score Range Invariant
- **Criteria**: 2.1, 2.5, 9.3
- **Property**: For all valid report documents, the `purityScore` field is always a number between 0 and 100 inclusive. Any attempt to store a value outside this range via the Admin_API results in a 400 error.
- **Type**: Invariant

### Property 2: Barcode Format Validation
- **Criteria**: 9.2
- **Property**: For all non-null barcode values stored in the Report_Collection, the barcode matches the pattern `/^\d{13}$/`. Any barcode value that does not match this pattern is rejected by the Admin_API with a 400 error.
- **Type**: Invariant

### Property 3: Required Fields Enforcement
- **Criteria**: 9.1, 9.4
- **Property**: For any report creation request missing one or more of the required fields (productName, brandName, category, imageUrl, purityScore, testParameters), the Admin_API returns a 400 status code and the response body lists all missing field names.
- **Type**: Error condition

### Property 4: Timestamp Auto-Population
- **Criteria**: 7.6, 7.7
- **Property**: For every document in the Report_Collection, `createdAt` is a valid Date set at insertion time, and `updatedAt` is a valid Date that is greater than or equal to `createdAt`. After any update operation, `updatedAt` is strictly greater than or equal to the previous `updatedAt` value.
- **Type**: Invariant

### Property 5: Lab Report Number Uniqueness
- **Criteria**: 8.5
- **Property**: For any two documents in the Report_Collection that both have a non-null `labReportNumber`, the values are distinct. Attempting to insert a document with a duplicate `labReportNumber` results in an error.
- **Type**: Invariant

### Property 6: Default Values on Creation
- **Criteria**: 7.8, 7.9, 6.2
- **Property**: When a report is created without specifying `published`, `isPremium`, or `comparisons`, the stored document has `published: true`, `isPremium: false`, and `comparisons: []`.
- **Type**: Idempotence / Default state

### Property 7: Partial Update Preservation
- **Criteria**: 9.5
- **Property**: When a report is updated with a subset of fields, all fields not included in the update request retain their previous values. Only the specified fields and `updatedAt` change.
- **Type**: Metamorphic (update with empty change set produces same document except updatedAt)

## Migration Notes

- Existing documents in `test_reports` will not have the new fields. The API and mobile app already handle missing fields gracefully (optional chaining, null checks).
- No data migration script is needed — new fields will be populated as reports are created or updated going forward.
- The new unique sparse index on `labReportNumber` will only enforce uniqueness for documents that have this field set, so existing documents without it are unaffected.
